## 추가한 자료 및 실행 코드
- `data/hexagonest-1595.b64` : 1595 영상 전용 60fps HXRF 벽 외곽선.
- `data/hexagonest-1596.b64` : 1596 영상 전용 60fps HXRF 벽 외곽선.
- `data/hexagonest-1595-palette.json` / `data/hexagonest-1596-palette.json` : 60fps 원본 추출 RGB 배경·벽 색상.
- `data/hexagonest-sources.json` : 영상별 타임코드/프레임 비율/원본 출처.
- `tools/extract_hexagonest.py` / `tools/extract_hexagonest_palette.py` : 전용 프레임 추출 도구. 재생에 원본 MP4 파일은 배포하지 않는다.
- `hexagonest-source.js` : 두 영상의 완전한 데이터와 시간축을 검증한 뒤 세 번째 맵을 등록.
- `hexagonest-chronology.js` : 시간 순서, 60초 경계, 독립된 벽 ID 조사.
- `engine.js` : 3번 맵에 한해 첫 0.55초의 원본 벽을 강제 삭제하는 기존 처리 제외. 1·2번의 시작 처리는 그대로 유지.
- `replay.js` : 3번 맵 독립 영상의 파싱·색상표 경로를 별도 지정. 1·2번의 파싱 분기는 보존.
- `play.js` : `?trace=1595`, `?trace=1596`로 원본 영상 순차 재생. 기본 3-1 실행은 첫 번째 원본의 순서 재생, **랜덤 연결 아님**.
- `test/hexagonest-real-films.test.cjs` 및 `test/hexagonest-opening.test.cjs`: 실데이터 디코딩/시작 충돌/60초 경계 회귀 검증 코드.
- `.github/workflows/hexagonest-3-1.yml` : 노드 회귀 테스트 GitHub Actions 설정.

## 실제 수행한 확인
- 원본 두 동영상에 대한 프레임 추출을 실제로 실행해 생성 데이터의 개수/바이너리 구조/마지막 시간 값을 재검증했다.
- 각 영상의 60초 직전/직후 전경 폴리곤을 직접 비교: **1595는 6개 중 6개, 1596은 2개 중 2개**가 바로 다음 프레임까지 이어지는 것을 확인했다.
- 각 프레임에서 캐릭터 궤도의 144개 방향을 샘플하여 모두 막힌 프레임은 없음을 확인(1595 5,664프레임, 1596 4,118프레임).
- 실제 영상 픽셀과 추출 벽 실루엣 비교(표본): 1595 게임시간 59.9초 **95.1%**, 92초 **97.6%**, 1596 게임시간 60.1초 **97.8%**의 픽셀 영역 IoU. 100% 일치로 주장하지 않는다.
- 초기에 잘못 검출된 색상/NEW RECORD HUD의 영향을 확인하고 벽 영역을 기준으로 RGB 색상표를 재측정했다.
- 이전 회귀 테스트는 V8에서 실합성 데이터로 통과했으나, 새 60fps 데이터의 실제 Node + Chromium E2E 실행 결과는 이 문서 작성 시점에 확인되지 않았다. GitHub Actions 워크플로는 등록했지만 완료/통과 여부는 아직 미확인이다.

## 아직 남은 차이 / 검증
1. 비디오 색상의 윤곽을 60fps로 전사한 것은 **원본의 정확한 엔진 벽 파라미터**를 복원한 것과 다르다. 색상 전환 중 윤곽 합침/쪼개짐, 최대 1~2픽셀 정도의 변환 편차가 남는다.
2. 카메라 위상·줌·도형 전환, 화면 비율·중앙 거리의 프레임별 직접 오차 검증이 미완료다. 현재 카메라 값은 코어 영상에서 추정한 값이며 영상과 완전히 같다고 단정하지 않는다.
3. 실제 브라우저에서 첫 시작/벽 통과/벽 충돌/즉사 여부/재시작과 1·2번 회귀 플레이를 자동화한 E2E 실행은 아직 미완료다.
4. 0~60/60초 이후 **파트 분할 수**는 아직 정해지지 않았다. 그 작업과 연속 회피 가능한 랜덤 연결은 **3-2**에서 수행한다.
5. HUD, 실제 캐릭터 회전속도, 음악/음성 동기화, 사망 이펙트·화면 떨림은 **3-2**에서 원본과 비교한다.

**3-1의 영상 데이터 추출·원본 순차 재생 코드 반영은 수행했으나, 브라우저 플레이/영상 프레임 대조 완성 승인은 미완료다. 따라서 3-2를 시작하지 않는다.**

### 이번 보정

`tools/extract_hexagonest.py`의 색상 탐지를 보정하여, 채도가 높은 원본 노란색/초록색 벽을 흰색 HUD 글자와 혼동하지 않게 했다. 특히 1595의 게임 시간 60초 부근에서 한 프레임 동안 모든 벽이 사라진 것으로 인식되던 색상 오검출을 줄였다. 1596의 시작부에는 거대한 중앙 도형 윤곽이 벽처럼 추출되어 초기 즉사 원인이 될 수 있었으므로, 영상 시작 0.60초의 해당 비벽 중심 윤곽은 벽 시퀀스에서 제외했다. 이미 내려오는 60초 벽들을 별도 패턴으로 다시 생성하지 않는다.

### 실행한 로컬 검증

- 재추출 60fps HXRF 두 개를 직접 압축 해제/프레임 파싱해 각 5,664 / 4,118 프레임 존재 확인.
- 기존 `replay.js`에 있는 위치·면적 추적 점수 방식과 같은 기준으로 60초 전후의 **연속 벽 ID가 1595에서 5개, 1596에서 2개**임을 측정. 최종 JS 런타임에서 추가 확인할 회귀 조건도 `test/hexagonest-real-films.test.cjs`에 넣었다.
- 반지름 66 월드 단위, 120방향 단면 점유를 10원본 프레임 간격으로 표본 검사: 1595 567개, 1596 412개 프레임에서 **전 방향 봉쇄 0개**. 이는 전체 구간의 회피 가능한 연속 조작 경로를 입증하지 않는다.
- 별도 54개(1595 32개, 1596 22개) 영상 샘플에 대해 원본 프레임의 *전경색 마스크*와 저장된 벽 폴리곤을 원본 화면 좌표로 그린 결과의 픽셀 IoU 중앙값은 **1595 0.952, 1596 0.945**. 이는 마스크→벡터 추출의 보존율로, 원본 게임 픽셀 완전 일치율이 아니며 카메라·음악·UI 일치를 보증하지 않는다.
- 실제 소스 파일을 읽는 Node 회귀 테스트 `test/hexagonest-real-films.test.cjs`에 60초 동일 벽 ID와 60fps 체크를 추가했다. 별도 로컬 Python 검사 결과와 달리, 해당 GitHub Actions 실행 로그와 Chromium 실플레이 결과는 이번 응답 시점에 직접 확인하지 못해 **실행 통과로 표시하지 않는다**.
