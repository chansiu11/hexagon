# 5-2 HYPER HEXAGONER — 연결기 구현과 검증 상태

기준 작업 5-1 브랜치: `rebuild-step-5-1-hyper-hexagoner-20261116` / `5290358bbe32a4f7ed4edcd4b19e6fab271d16cf`

작업 브랜치: `rebuild-step-5-2-hyper-hexagoner-20261117`.

## 실제 반영한 코드

- `hyper-hexagoner-parts.js`: 다른 맵의 생성기나 벽 컨투어를 사용하지 않고, 5-1의 **독립적으로 검증된 두 원본**의 프레임만 받아 재생하는 파트 연결기다.
- 각 원본 녹화 시간의 실측 보정값 `gameRate`, `gameStartOffset`으로 **게임 시간 60초** 경계 프레임을 별도로 구한다. 60초 전후의 파트 그룹을 구분하고, 벽 ID, 각형 전환, 화면 회전/줌 연속성을 반영한다.
- 연결 파트는 원본의 프레임 순서를 유지한다. 벽 밀도와 변형 구간을 살펴 낮은 위험도의 절단 후보를 우선한다. **이 절단은 영상 원본의 회피 동작 단위와 시각적으로 아직 대조되지 않았다.**
- 파트 경계에서는 기존 벽 ID를 이어 가지고, 원본 프레임의 같은 ID가 사라질 때까지 해당 원본에서 이어서 추적한다. 다른 파트의 시작 프레임에 이미 진행 중이던 벽은 새로 생성하지 않는다.
- 다음 파트를 고를 때 실제 플레이어 각속도, 복수 시점의 폴리곤 충돌, 중간 회전 경로, 1초 이내 새 벽 등장 시간을 검사한다. 검사를 만족하는 다음 파트가 없으면 가짜 통로 또는 순간 벽을 만들어 연결하지 않고 경로를 종료한다.
- 게임의 기본 5번 맵은 **두 영상 랜덤 연결**을 요청한다. `?trace=1595` 또는 `?trace=1596`은 각 원본의 시간순 진단 경로, `?seed=18&first=1595`는 시드 고정 랜덤 재생 경로다.
- 5번 맵의 HUD를 구형 맵과 분리해 임시 구현했고, 공용 플레이어 조작 모드 1/2/3, 시간, 사망/재시작, 소리 재생, 메뉴 돌아가기를 연결했다. 기존 1~4번 맵 코드는 원상 유지했다. 7번 맵을 부활시키지 않았다.

## 테스트

- 5-2 단위 테스트: 두 소스 모두 필수, 60초 전/후 원본 시간축 분리, source-cut 중 중복/갑작스런 벽 생성 방지, 랜덤 60초 이후 진행, 60초 중 살아 있는 벽 ID 유지, 벽 접촉 사망 및 열린 통로 판정.
- 1초 등장 간격을 검사하는 추가 테스트에서 이전 구현은 합성 데이터상 최대 1.52초 공백이 발견됐다. 이후 **마지막 실제 벽 등장 시각 + 다음 후보의 최초 등장 지연**을 합산하여 연결을 거부하도록 수정했다.
- GitHub Actions: Node.js 단위 테스트, Playwright Chromium 기반 5번 맵 진입/두 소스 선택/랜덤 파트 전환/0~60/60초 이후/메뉴 복귀, 기존 1~4번 단계 회귀 검사.
- 모든 5번 맵 테스트에서 사용된 합성 비디오 JSON은 테스트 과정에서만 네트워크 인터셉트로 공급되며, 실제 소스 파일을 대체하여 배포하지 않는다.

## 아직 미완료 — 절대 원작 재현 완료로 표시하지 않을 항목

- 원본 `1595(4).mp4`, `1596(4).mp4`는 대화에 첨부됐으나 영상 디코딩 런타임이 실패하여 **해당 두 영상의 실제 프레임이 현재 작업에서 추출되지 않았다.**
- `data/hyper-hexagoner-1595.json`, `...1596.json`이 없으므로 **정식 사이트의 5번 맵은 아직 재생 자료를 불러올 수 없다**. 구형 다섯 번째 맵 패턴으로 자동 대체하거나 미검증 패턴을 창작해 재생하지 않는다.
- 원본의 게임 시간 0~60 및 60초 이후 실제 플레이 범위, 각 영상의 파트 수, 벽 생성·두께·간격·도형 변형·카메라 회전/줌/떨림·음성의 정밀 원본 일치 여부는 **미확인**. 색상/HUD는 영상 대조 전 **임시 값**이다.
- 1초 등장 간격 검사와 플레이 통로 유효성은 합성 데이터에서는 성공했지만, 실제 영상 녹화에 동일하게 성립한다고 말할 수 없다. 동적 경계 분석은 원본 벽 ID 추적의 정확도에도 의존한다.

**작업 6은 시작하지 않았다.**

## 5-2 후속 수정 — 다른 영상으로 연결할 때 기존 벽 화면 좌표 고정

- 이전 구현의 벽 유지 방식은 벽 ID와 필름의 다각형 좌표를 보존했지만, **다른 필름의 회전·확대 카메라로 바뀌면 잔존 벽이 새 카메라를 따라 움직일 위험**이 있었다.
- `hyper-hexagoner-parts.js`에 이어지는 옛 벽의 영상별 카메라 회전 보정량(`cameraOffset`) 및 확대 보정량(`zoomRatio`)을 저장했다. 각 프레임에서 옛 원본의 화면 좌표를 새 카메라 월드 좌표로 다시 변환하여, 옛 벽의 예상 화면 위치와 충돌 위치가 동일하도록 수정했다.
- 다음 파트의 안전한 통로를 검색할 때도 같은 변환을 적용하므로, 새 영상 카메라에서 이전 벽을 고려하지 않아 갑자기 막힌 길을 고르는 일을 방지했다.
- 추가 합성 영상 테스트는 영상 A/B의 회전속도와 확대 비율을 다르게 설정하고, 연결 시점과 연결 후 여러 프레임에서 **변환된 벽의 화면 좌표 오차가 0.00001 미만**인지 확인한다.
- 기존 5-1/5-2 테스트와 완료된 1~4번 맵 회귀 검사를 함께 실행했다. 이는 합성 프레임의 코드 검증이며 **실제 첨부 원본과의 픽셀 대조 결과가 아니다**.
- 두 첨부 MP4의 실프레임 디코딩과 HYPER HEXAGONER 원본 JSON 추출은 이 실행 환경에서 계속 `ClientError`를 반환하여 미완료다.
